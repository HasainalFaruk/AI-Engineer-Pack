# RAG Checklist

- [ ] The affected RAG files, configuration, and runtime path are identified.
- [ ] Existing repository conventions and dependency versions are respected.
- [ ] The solution avoids poor chunking, stale indexes, missing source attribution, irrelevant top-k retrieval, and no answerability threshold.
- [ ] Security, reliability, and maintainability concerns are reviewed.
- [ ] Verification includes retrieval evals, citation checks, chunk inspection, latency tests, and hallucination probes.
- [ ] Documentation or examples are updated when setup, behavior, or usage changes.
- [ ] The final summary names residual risks and any checks not run.
