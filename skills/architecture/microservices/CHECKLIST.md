# Microservices Checklist

- [ ] The affected Microservices files, configuration, and runtime path are identified.
- [ ] Existing repository conventions and dependency versions are respected.
- [ ] The solution avoids distributed monoliths, shared databases, chatty APIs, unclear ownership, and missing correlation IDs.
- [ ] Security, reliability, and maintainability concerns are reviewed.
- [ ] Verification includes contract tests, dependency mapping, resilience checks, tracing review, and deployment boundary validation.
- [ ] Documentation or examples are updated when setup, behavior, or usage changes.
- [ ] The final summary names residual risks and any checks not run.
