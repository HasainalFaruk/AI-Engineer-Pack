# Event-Driven Architecture Checklist

- [ ] The affected Event-Driven Architecture files, configuration, and runtime path are identified.
- [ ] Existing repository conventions and dependency versions are respected.
- [ ] The solution avoids ambiguous event names, no idempotency, hidden ordering assumptions, unbounded retries, and missing event ownership.
- [ ] Security, reliability, and maintainability concerns are reviewed.
- [ ] Verification includes schema compatibility checks, replay tests, idempotency tests, dead-letter handling, and observability review.
- [ ] Documentation or examples are updated when setup, behavior, or usage changes.
- [ ] The final summary names residual risks and any checks not run.
