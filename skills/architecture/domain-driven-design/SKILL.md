# Domain-Driven Design Skill Definition

## Capability
Use this skill for bounded contexts, aggregates, value objects, domain services, ubiquitous language, and context mapping. The assistant should inspect local conventions first, choose technology-appropriate patterns, and verify results with model walkthroughs, invariant tests, boundary reviews, repository contract checks, and language consistency checks.

## Best for
- Designing or modifying Domain-Driven Design-specific code, configuration, documentation, or tests.
- Reviewing implementation risks and maintainability concerns.
- Debugging failures that depend on Domain-Driven Design tooling or runtime behavior.
- Creating prompts or workflows that require accurate Domain-Driven Design terminology.

## Inputs
- User goal, acceptance criteria, and affected environment.
- Relevant source files, config files, dependencies, logs, or test output.
- Version constraints and deployment context.
- Security, performance, accessibility, reliability, or maintenance requirements.

## Outputs
- Focused plan, implementation, review, or debugging guidance.
- Technology-specific risks, tradeoffs, and verification steps.
- Updated docs or examples when behavior or usage changes.

## Watch for
Avoid anemic models, leaking persistence concerns, oversized aggregates, unclear boundaries, and jargon without domain meaning.
