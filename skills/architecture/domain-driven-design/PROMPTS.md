# Domain-Driven Design Prompts

## Build
Use the Domain-Driven Design skill. Inspect existing project conventions, implement the requested change using idiomatic Domain-Driven Design patterns, verify with model walkthroughs, invariant tests, boundary reviews, repository contract checks, and language consistency checks, and summarize changed files and risks.

## Review
Use the Domain-Driven Design skill. Review the change for correctness, maintainability, security, performance, and Domain-Driven Design-specific pitfalls such as anemic models, leaking persistence concerns, oversized aggregates, unclear boundaries, and jargon without domain meaning. Provide findings by severity.

## Debug
Use the Domain-Driven Design skill. Reproduce or reason through the issue, inspect relevant files and runtime signals, identify the likely cause, apply a focused fix if requested, and verify with model walkthroughs, invariant tests, boundary reviews, repository contract checks, and language consistency checks.

## Document
Use the Domain-Driven Design skill. Create documentation that explains setup, usage, configuration, limitations, and troubleshooting for this repository's Domain-Driven Design implementation.
