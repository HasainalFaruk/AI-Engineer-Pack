# Domain-Driven Design Checklist

- [ ] The affected Domain-Driven Design files, configuration, and runtime path are identified.
- [ ] Existing repository conventions and dependency versions are respected.
- [ ] The solution avoids anemic models, leaking persistence concerns, oversized aggregates, unclear boundaries, and jargon without domain meaning.
- [ ] Security, reliability, and maintainability concerns are reviewed.
- [ ] Verification includes model walkthroughs, invariant tests, boundary reviews, repository contract checks, and language consistency checks.
- [ ] Documentation or examples are updated when setup, behavior, or usage changes.
- [ ] The final summary names residual risks and any checks not run.
