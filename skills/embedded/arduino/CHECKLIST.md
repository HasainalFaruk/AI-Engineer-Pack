# Arduino Checklist

- [ ] The affected Arduino files, configuration, and runtime path are identified.
- [ ] Existing repository conventions and dependency versions are respected.
- [ ] The solution avoids blocking delays, floating inputs, memory fragmentation, wrong voltage assumptions, and pin conflicts.
- [ ] Security, reliability, and maintainability concerns are reviewed.
- [ ] Verification includes compile checks, serial monitor validation, pin mapping review, timing tests, and hardware smoke tests.
- [ ] Documentation or examples are updated when setup, behavior, or usage changes.
- [ ] The final summary names residual risks and any checks not run.
