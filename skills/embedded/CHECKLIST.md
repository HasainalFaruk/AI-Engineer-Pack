# Embedded Checklist

- [ ] The request and definition of done are clear.
- [ ] Relevant repository context has been inspected.
- [ ] The approach follows existing conventions.
- [ ] Edge cases and failure modes have been considered.
- [ ] Security and privacy implications are reviewed where applicable.
- [ ] Tests or verification cover the changed behavior.
- [ ] Documentation is updated if setup, behavior, or usage changed.
- [ ] The final summary includes changes, verification, and residual risks.
