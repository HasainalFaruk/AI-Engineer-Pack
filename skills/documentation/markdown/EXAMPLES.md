# Markdown Examples

## Implementation example
Request: Use the Markdown skill to add a small feature in the current repository, follow existing conventions, and verify with heading review, link checks, code fence balance, command accuracy, and readability pass.

Expected output: A focused implementation summary, changed files, verification results, and notes about Markdown-specific risks.

## Review example
Request: Use the Markdown skill to review a pull request for correctness and risks.

Expected output: Severity-ranked findings that call out issues such as broken relative links, stale commands, inconsistent headings, placeholder text, and examples without context.

## Debugging example
Request: Use the Markdown skill to investigate a failure involving README files, guides, checklists, tables, links, code fences, and GitHub-friendly documentation.

Expected output: Root cause, focused fix or recommendation, verification evidence, and remaining uncertainty.
