# Markdown Checklist

- [ ] The affected Markdown files, configuration, and runtime path are identified.
- [ ] Existing repository conventions and dependency versions are respected.
- [ ] The solution avoids broken relative links, stale commands, inconsistent headings, placeholder text, and examples without context.
- [ ] Security, reliability, and maintainability concerns are reviewed.
- [ ] Verification includes heading review, link checks, code fence balance, command accuracy, and readability pass.
- [ ] Documentation or examples are updated when setup, behavior, or usage changes.
- [ ] The final summary names residual risks and any checks not run.
