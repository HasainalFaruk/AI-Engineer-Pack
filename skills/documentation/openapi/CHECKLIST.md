# OpenAPI Checklist

- [ ] The affected OpenAPI files, configuration, and runtime path are identified.
- [ ] Existing repository conventions and dependency versions are respected.
- [ ] The solution avoids undocumented errors, loose schemas, missing auth details, stale examples, and implementation-contract drift.
- [ ] Security, reliability, and maintainability concerns are reviewed.
- [ ] Verification includes schema validation, example request checks, response contract tests, and generated docs review.
- [ ] Documentation or examples are updated when setup, behavior, or usage changes.
- [ ] The final summary names residual risks and any checks not run.
