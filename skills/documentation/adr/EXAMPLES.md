# Architecture Decision Records Examples

## Implementation example
Request: Use the Architecture Decision Records skill to add a small feature in the current repository, follow existing conventions, and verify with decision completeness review, link checks, status review, and consistency with implementation.

Expected output: A focused implementation summary, changed files, verification results, and notes about Architecture Decision Records-specific risks.

## Review example
Request: Use the Architecture Decision Records skill to review a pull request for correctness and risks.

Expected output: Severity-ranked findings that call out issues such as recording decisions after the fact without tradeoffs, vague consequences, missing owners, and stale status.

## Debugging example
Request: Use the Architecture Decision Records skill to investigate a failure involving decision records that capture context, options, decision, consequences, and follow-up review triggers.

Expected output: Root cause, focused fix or recommendation, verification evidence, and remaining uncertainty.
