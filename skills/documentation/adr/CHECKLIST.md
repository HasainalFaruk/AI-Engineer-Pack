# Architecture Decision Records Checklist

- [ ] The affected Architecture Decision Records files, configuration, and runtime path are identified.
- [ ] Existing repository conventions and dependency versions are respected.
- [ ] The solution avoids recording decisions after the fact without tradeoffs, vague consequences, missing owners, and stale status.
- [ ] Security, reliability, and maintainability concerns are reviewed.
- [ ] Verification includes decision completeness review, link checks, status review, and consistency with implementation.
- [ ] Documentation or examples are updated when setup, behavior, or usage changes.
- [ ] The final summary names residual risks and any checks not run.
