# Secrets Management Examples

## Implementation example
Request: Use the Secrets Management skill to add a small feature in the current repository, follow existing conventions, and verify with secret scanning, least-privilege access review, rotation runbooks, local env checks, and CI log review.

Expected output: A focused implementation summary, changed files, verification results, and notes about Secrets Management-specific risks.

## Review example
Request: Use the Secrets Management skill to review a pull request for correctness and risks.

Expected output: Severity-ranked findings that call out issues such as committed secrets, broad secret access, no rotation path, secrets in logs, and mixing dev and prod credentials.

## Debugging example
Request: Use the Secrets Management skill to investigate a failure involving secret storage, rotation, environment configuration, vault integration, CI/CD secrets, and leak prevention.

Expected output: Root cause, focused fix or recommendation, verification evidence, and remaining uncertainty.
