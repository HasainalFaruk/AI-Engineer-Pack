# Secrets Management Checklist

- [ ] The affected Secrets Management files, configuration, and runtime path are identified.
- [ ] Existing repository conventions and dependency versions are respected.
- [ ] The solution avoids committed secrets, broad secret access, no rotation path, secrets in logs, and mixing dev and prod credentials.
- [ ] Security, reliability, and maintainability concerns are reviewed.
- [ ] Verification includes secret scanning, least-privilege access review, rotation runbooks, local env checks, and CI log review.
- [ ] Documentation or examples are updated when setup, behavior, or usage changes.
- [ ] The final summary names residual risks and any checks not run.
