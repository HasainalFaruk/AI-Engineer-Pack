# Azure Checklist

- [ ] The affected Azure files, configuration, and runtime path are identified.
- [ ] Existing repository conventions and dependency versions are respected.
- [ ] The solution avoids overbroad roles, secrets in app settings, missing managed identities, and unclear resource ownership.
- [ ] Security, reliability, and maintainability concerns are reviewed.
- [ ] Verification includes role assignment review, deployment plan checks, Key Vault access tests, logs, metrics, and health probes.
- [ ] Documentation or examples are updated when setup, behavior, or usage changes.
- [ ] The final summary names residual risks and any checks not run.
