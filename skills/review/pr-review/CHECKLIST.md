# Pull Request Review Checklist

- [ ] The affected Pull Request Review files, configuration, and runtime path are identified.
- [ ] Existing repository conventions and dependency versions are respected.
- [ ] The solution avoids approving without reading related code, ignoring failing checks, scope creep, and no rollback thinking.
- [ ] Security, reliability, and maintainability concerns are reviewed.
- [ ] Verification includes CI review, diff review, acceptance criteria checks, documentation review, and release risk review.
- [ ] Documentation or examples are updated when setup, behavior, or usage changes.
- [ ] The final summary names residual risks and any checks not run.
