# Security Review Checklist

- [ ] The affected Security Review files, configuration, and runtime path are identified.
- [ ] Existing repository conventions and dependency versions are respected.
- [ ] The solution avoids checking only dependencies, missing authorization paths, ignoring logs, and treating authentication as complete security.
- [ ] Security, reliability, and maintainability concerns are reviewed.
- [ ] Verification includes threat model pass, secret scan review, dependency checks, auth tests, and exploit-oriented test cases.
- [ ] Documentation or examples are updated when setup, behavior, or usage changes.
- [ ] The final summary names residual risks and any checks not run.
