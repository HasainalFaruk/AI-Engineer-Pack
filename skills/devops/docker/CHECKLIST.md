# Docker Checklist

- [ ] The affected Docker files, configuration, and runtime path are identified.
- [ ] Existing repository conventions and dependency versions are respected.
- [ ] The solution avoids running as root, copying secrets, bloated layers, missing health checks, and dev-only settings in production images.
- [ ] Security, reliability, and maintainability concerns are reviewed.
- [ ] Verification includes docker build, compose smoke tests, image inspection, health checks, and dependency cache validation.
- [ ] Documentation or examples are updated when setup, behavior, or usage changes.
- [ ] The final summary names residual risks and any checks not run.
