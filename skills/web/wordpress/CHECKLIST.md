# WordPress Checklist

- [ ] The affected WordPress files, configuration, and runtime path are identified.
- [ ] Existing repository conventions and dependency versions are respected.
- [ ] The solution avoids missing escaping, missing nonces, direct database queries, global state surprises, and update-unsafe customizations.
- [ ] Security, reliability, and maintainability concerns are reviewed.
- [ ] Verification includes local WordPress smoke tests, PHP linting, nonce checks, role checks, and plugin activation tests.
- [ ] Documentation or examples are updated when setup, behavior, or usage changes.
- [ ] The final summary names residual risks and any checks not run.
